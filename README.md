# Delta Console

Веб-панель управления модульной экосистемой личных данных и автоматизации.
Консоль сама является плагином: она подключается к центральному ядру Delta через API и **не знает заранее**, какие плагины установлены — интерфейс строится по их контрактам.

```
npm install
npm run dev          # демо-режим: mock-ядро в браузере, http://localhost:5173
npm run dev:http     # реальное ядро (VITE_CORE_URL в .env.http)
npm run build        # typecheck + production-сборка в dist/
npm test             # юнит-тесты контрактов, реестра, раскладки
```

Готовая сборка лежит в `dist/` (относительные пути, HashRouter) — её можно открыть через любой статический сервер: `npx vite preview` или `python3 -m http.server -d dist`.

## Архитектура

```
src/
  core/            чистый TypeScript, без React — можно переиспользовать в ядре/CLI
    contracts/     zod-схемы и типы: плагин, метрика, узел, события, доступ, дашборд
    contracts/validate.ts   валидация манифеста: схема → семантика → совместимость
    registry/      WidgetRegistry (подбор визуализаций, версии, миграции),
                   нормализация плагинов, автогенерация дашбордов, упаковщик сетки
    lib/           semver, форматирование, детерминированный PRNG
  api/
    types.ts       интерфейс CoreApi — единственная граница UI ↔ ядро
    mock/          MockCoreAdapter: полноценная симуляция ядра (localStorage)
    http/          HttpCoreAdapter: REST + WebSocket /stream с переподключением
    index.ts       фабрика адаптера (mock | http)
  app/             кэш запросов (SWR), сторы (zustand), тема, права (useCan)
  ui/              дизайн-система: примитивы, оверлеи, состояния, иконки
  widgets/         реализации виджетов + регистрация в реестре
  dashboards/      сетка (react-grid-layout), рамка виджета, редактор, ErrorBoundary
  layout/          оболочка, сайдбар, топбар, ⌘K-палитра, уведомления, realtime-мост
  pages/           разделы консоли
```

Компоненты получают API только через `<ApiProvider>`; ни один компонент не импортирует адаптер напрямую. Переключение mock ↔ real — в «Настройки → Подключение к ядру» или переменными окружения `VITE_CORE_MODE`/`VITE_CORE_URL`.

### Контракт плагина → интерфейс

1. Ядро отдаёт сырые манифесты (`unknown`). Консоль валидирует каждый (`validateManifest`): zod-схема, семантические проверки (дубликаты, ссылки измерений, агрегации), совместимость `contract` с версией панели (`1.4.0`), неизвестные визуализации и capabilities.
2. Несовместимый плагин не ломает консоль: он виден в каталоге с отчётом, установка блокирована. Неизвестные визуализации/возможности — предупреждение, используется лучший известный виджет.
3. `WidgetRegistry.rank(metric)` оценивает каждый зарегистрированный тип виджета по виду метрики, измерениям и подсказкам плагина. Из этого строятся автодашборды плагинов и список в редакторе виджета.
4. Сохранённые виджеты хранят `type` + `typeVersion`. При загрузке `resolve()` даёт `ok | migrated | incompatible | unknown`; каждый случай имеет своё состояние в рамке виджета.

## Разделы

- **Обзор** — настраиваемая домашняя страница (это обычный дашборд с origin `home`) + сводная строка.
- **Дашборды** — пользовательские и автоматические; drag & resize, редактор виджета с превью, диапазоны, сравнение с прошлым периодом, легенды, палитры, пороги, экспорт CSV/JSON, импорт.
- **Плагины** — каталог, установка (3 шага: узлы → разрешения → настройки), обновление, отключение, удаление, настройки из схемы, разрешения, узлы, логи, отчёт контракта.
- **Узлы** — статус, нагрузка, история CPU/памяти/задержки, доступность 90 дней, процессы, компоненты с перезапуском, ошибки, события, команды в рамках политики узла и роли, параметры подключения, сопряжение нового узла.
- **События** — единый журнал с фильтрами, live-потоком, паузой, подгрузкой, деталями.
- **Контракты** — песочница валидатора манифестов, реестр виджетов и матрица совместимости, спецификация.
- **Доступ** — участники и токены, роли, матрица прав, аудит, «просмотр от имени роли».
- **Настройки** — интерфейс, подключение к ядру, импорт/экспорт конфигурации с предпросмотром, симуляция сбоев (только mock).

## Демо-сценарии

| Сценарий | Где |
|---|---|
| Обновить «Анализ печати» 2.4.1 → 2.5.0 | Плагины → Обновления |
| Установить «Метеостанцию» | Плагины → Каталог |
| Починить «Историю браузера» (AUTH_EXPIRED) — ввести новый токен синхронизации | Плагины → История браузера → Настройки |
| Переподключить «Дом» | карточка плагина → Переподключить |
| hel-backup: DISK_PRESSURE → команда «Очистить кэш» | Узлы → hel-backup → Команды |
| Перезапустить упавший компонент | Узлы → hel-backup → Компоненты |
| Плагин с неизвестной визуализацией `geo-map` | Плагины → Геотрекер |
| Плагин с несовместимым контрактом `^2.0.0` и битый манифест | Плагины → Проблемы, Контракты |
| Собрать свой дашборд, перетащить/растянуть виджеты | Дашборды → Создать |
| Проверить права | Доступ → Просмотр от имени роли «Наблюдатель» |
| Медленная сеть / 30% ошибок / ядро офлайн | Настройки → Симуляция |
| Экспорт и импорт конфигурации | Настройки → Импорт и экспорт |

Сброс демо-данных — «Настройки → Симуляция → Сбросить».

## Горячие клавиши

`⌘K` / `Ctrl K` или `/` — глобальный поиск и команды; `Esc` — закрыть оверлей.
